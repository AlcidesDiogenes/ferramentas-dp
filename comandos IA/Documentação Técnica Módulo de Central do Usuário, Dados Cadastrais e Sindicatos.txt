================================================================================
DOCUMENTAÇÃO TÉCNICA: MÓDULO DE CENTRAL DO USUÁRIO, DADOS CADASTRAIS E SINDICATOS
================================================================================

1. VISÃO GERAL DA ARQUITETURA
--------------------------------------------------------------------------------
* Integração e Lógica: O módulo atua como um controlador central de interface e lógica assíncrona, com integração direta ao serviço de autenticação e ao banco de dados do Supabase.
* Gestão e Persistência: A arquitetura gerencia sessões ativas de usuários, executa operações de persistência relacional e consome dados do esquema público.
* Objetivo: Estruturar e alimentar o painel de gerenciamento de perfil e Convenções Coletivas de Trabalho (CCT).


2. MAPEAMENTO DE COMPONENTES E INTERFACE
--------------------------------------------------------------------------------
* Navegação Modular: Utiliza botões de abas para alternar seções, manipulando dinamicamente classes de estado ativo (active e active-section) e ocultando blocos inativos.
* Tabelas Dinâmicas: Exibe os sindicatos cadastrados (Nome, CNPJ, Data Base, Fim da vigência). Caso a base retorne vazia, a tabela é ocultada para exibir uma mensagem de "empty state".
* Pop-up Modal: Formulário flutuante (modal overlay) de registro de sindicatos, invisível por padrão e acionado exclusivamente por botão de gatilho.
* Mecanismos de Reset: O fechamento do modal (botões dedicados ou clique no fundo) engatilha obrigatoriamente a limpeza dos inputs e a ocultação de blocos condicionais.


3. REGRAS DE NEGÓCIO E PROCESSAMENTO DE DADOS
--------------------------------------------------------------------------------
* Validação Inicial: No carregamento, o sistema requisita as credenciais do usuário autenticado no Supabase e armazena o identificador único para governar as requisições.
* Carga de Dados Pessoais: A aba Dados Cadastrais exibe "E-mail de Acesso" (somente leitura), "Nome que deseja usar", "WhatsApp" e "Cargo", populados via consulta à tabela de perfis.
* Atualização Cadastral: A submissão valida o ID ativo, higieniza os textos (trim) e executa uma gravação otimizada (upsert), emitindo feedback visual com temporizador de 3 segundos.
* Cadastro de Sindicatos e Tratamento de CNPJ: O modal exige preenchimento obrigatório de Nome, CNPJ, Data base e Vigência da CCT atual. O campo de CNPJ conta com tratamento específico, aceitando o formato alfanumérico (conforme nova regra vigente) e limitando rigorosamente a digitação ao número máximo de caracteres permitidos para um CNPJ.
* Múltiplos Aditivos Condicionais: O botão "+ Adicionar Aditivo" e os respectivos campos de preenchimento só se tornam visíveis se a caixa de seleção perguntando se possui termo aditivo estiver marcada. Uma vez liberados, o sistema solicita o "Código do aditivo" e "Fim da vigência", permitindo adicionar quantos aditivos o usuário desejar.
* Persistência Sindical: A gravação une os dados base do sindicato com a lista de aditivos, insere na tabela user_sindicatos, fecha o modal e recarrega a listagem tabular.
* Exclusão de CCTs: Para cada CCT listada na tabela, existe um botão de exclusão dedicado. O acionamento deste botão dispara obrigatoriamente uma pergunta de confirmação na tela. Somente após a confirmação afirmativa do usuário o sistema realiza a exclusão do registro na base de dados e atualiza a listagem.


4. TRATAMENTO DE ESTADOS E FLUXOS
--------------------------------------------------------------------------------
* Reatividade de Listagem: O processamento das consultas ordena os registros de forma decrescente por data de criação.
* Estados Vazios: Se o retorno for nulo ou vazio, a tabela aplica "display: none" e a mensagem de ausência de cadastros recebe "display: block".
* Renderização Tabular: Existindo dados, a tabela é exibida, o corpo (tbody) é limpo e as linhas são injetadas dinamicamente via DOM, listando as informações e todos os aditivos atrelados.
* Feedback Assíncrono: O salvamento de dados emprega cores de destaque para orientar o usuário: Amarelo para processamento em andamento, Verde para sucesso, e Vermelho para erros interceptados.
