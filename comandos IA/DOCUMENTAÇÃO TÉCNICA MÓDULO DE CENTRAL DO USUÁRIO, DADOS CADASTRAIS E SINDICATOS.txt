================================================================================
DOCUMENTAÇÃO TÉCNICA: MÓDULO DE CENTRAL DO USUÁRIO, DADOS CADASTRAIS E SINDICATOS
================================================================================

1. VISÃO GERAL DA ARQUITETURA
--------------------------------------------------------------------------------
* O módulo atua como um controlador central de interface e lógica assíncrona, estabelecendo integração direta com o serviço de autenticação e o banco de dados do Supabase.
* A arquitetura gerencia sessões ativas de usuários, executa operações de persistência relacional e consome dados do esquema público para estruturar o painel de gerenciamento de perfil e Convenções Coletivas de Trabalho (CCT).


2. MAPEAMENTO DE COMPONENTES E INTERFACE
--------------------------------------------------------------------------------
* Navegação Modular por Abas: A interface disponibiliza seletores de navegação interna baseados em botões de abas e seções de formulário, gerindo a exibição visual por meio da alternância dinâmica de classes de estado ativo (active e active-section) e ocultação de blocos inativos.
* Tabelas Dinâmicas e Gestão de Estados: Na seção de Sindicatos, um quadro apresenta os registros cadastrados contendo as colunas: Nome, CNPJ, Data Base e Fim da vigência atual. Caso não exista nenhum sindicato cadastrado, o sistema ajusta a visibilidade para ocultar a tabela e apresenta uma mensagem textual informando que não há registros (empty state).
* Pop-up Modal de Cadastro: Ao clicar no botão de cadastrar sindicato, o formulário de registro é aberto encapsulado em uma camada de sobreposição flutuante (modal overlay), que se mantém invisível por padrão até este gatilho ser acionado.
* Mecanismos de Fechamento e Reset: O modal dispõe de botões dedicados de encerramento e cancelamento, além de suportar o fechamento por clique externo na área de fundo. Qualquer ação de fechamento dispara obrigatoriamente a limpeza de campos de input e a ocultação de sub-blocos condicionais.


3. REGRAS DE NEGÓCIO E PROCESSAMENTO DE DADOS
--------------------------------------------------------------------------------
* Validação Inicial de Sessão e Identidade: No carregamento do script, o sistema requisita as credenciais do usuário autenticado no Supabase, armazenando globalmente o identificador único (usuarioAtualId) para governar as requisições de leitura e escrita.
* Sincronização e Carga de Dados Pessoais (Dados Cadastrais): A aba de Dados Cadastrais exibe estritamente os seguintes campos: "E-mail de Acesso" (injetado automaticamente como somente leitura), "Nome que deseja usar", "WhatsApp" e "Cargo". Estes campos são populados com base na consulta à tabela de perfis filtrada pelo ID do usuário.
* Processamento de Atualização Cadastral: A submissão do formulário de perfil valida a existência do ID ativo, higieniza os valores de texto removendo espaços laterais excedentes (trim) e executa uma operação otimizada de gravação (upsert) na tabela de perfis. O processo emite feedback visual com código de cores e um temporizador de 3 segundos para limpeza da mensagem.
* Cadastro de Sindicato e Regras Condicionais para Aditivos: O pop-up modal solicita obrigatoriamente: "Nome do sindicato", "CNPJ", "Data base" e "Fim da vigência da CCT atual". Em seguida, o sistema pergunta se a convenção possui aditivo. 
* Múltiplos Aditivos: Se a resposta para o aditivo for afirmativa, o sistema libera dinamicamente os campos para o cadastro, solicitando o "Código do aditivo" e o "Fim da vigência do aditivo". A estrutura lógica permite que o usuário cadastre quantos aditivos desejar para a mesma convenção.
* Persistência de Vínculos Sindicais: A gravação de novos registros valida o usuário logado, consolida os dados base do sindicato em conjunto com todos os aditivos informados e executa a inserção na tabela user_sindicatos, seguida do fechamento automático do modal e recarregamento da listagem.
* Exclusão de Registros: A exclusão opera por meio de uma função global (window.deletarSindicato) atrelada aos botões do quadro de sindicatos. A função valida o consentimento do usuário via caixa de confirmação (confirm) antes de remover o item na base de dados e atualizar a listagem.


4. TRATAMENTO DE ESTADOS E FLUXOS
--------------------------------------------------------------------------------
* Reatividade de Listagem e Estados Vazios: O sistema processa o resultado das consultas ordenando os registros de forma decrescente por data de criação. Se o retorno for nulo ou vazio, a tabela HTML é ocultada (display: none) e a mensagem informando a ausência de cadastros é ativada (display: block).
* Renderização de Linhas Tabulares: Existindo dados, o quadro de sindicatos é exibido, o corpo tabular (tbody) é limpo para evitar duplicações e as novas linhas (tr) são injetadas dinamicamente via DOM (innerHTML), listando claramente o Nome, CNPJ, Data Base, Fim da vigência atual e os aditivos atrelados.
* Feedback Operacional Assíncrono: Durante o salvamento de dados pessoais, o sistema emprega atualizações dinâmicas de texto e cores de destaque — código amarelo (#fbbf24) para indicação de "Salvando...", verde (#4ade80) para sucesso e vermelho (#f87171) para captura e exibição de erros (catch) — orientando o usuário de forma clara sobre o status do processamento.
